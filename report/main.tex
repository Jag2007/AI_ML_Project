\begin{abstract}
``Two things move together'' does not mean ``one causes the other''. The Corr2Cause dataset tests exactly
this. Each example gives a short text listing which variables are related, and a claim such as ``A directly
causes B''. The task is to say whether the claim is definitely true (1) or not (0). We solved it in five steps,
one notebook per team member: clean the data, turn the text into a cause-and-effect graph, build features, train
classifiers, and finally draw the predicted graph and ask it ``what if'' questions. Using only the words of the
text, our model scores an F1 of 0.47. Adding the graph-based features raises this to 0.88. By reading the
dataset generator's code we matched its exact claim definitions, so the graph step alone (no learning) reproduces
98.5\% of the test labels. Our final model, a Random Forest, scores an F1 of 0.957 on the unseen test set, close
to the 0.952 of the no-learning rule. 89\% of the cause arrows it draws are correct, and our graphs answer 92 of 96
``what if'' questions correctly, against 0 of the 32 real effects for an empty or a reversed graph.
\end{abstract}

\section{Introduction}
\textbf{The problem.} Ice cream sales and drowning cases both go up in summer. They are \emph{correlated}, but
ice cream does not cause drowning; hot weather causes both. Large language models often make this mistake and
read correlation as causation.

\textbf{The dataset.} Corr2Cause~\cite{jin2024} turns this into a yes/no task. Here is a real example (shortened):
\begin{quote}\small
\emph{Premise:} There is a closed system of 3 variables, A, B and C. A correlates with B. A is independent of C.
B is independent of C.\\
\emph{Hypothesis:} There is a common effect (collider) of A and C.\\
\emph{Label:} 0 (not valid)
\end{quote}
The \emph{premise} lists which pairs of variables are related (``correlate'') and which are not (``independent'').
The \emph{hypothesis} is a claim about cause and effect. The label is 1 only if the claim is true in
\emph{every} cause-and-effect picture that fits the premise. If even one fitting picture breaks the claim, the
label is 0.

\textbf{Our goal.} Instead of a black box, we wanted a pipeline where every prediction can be traced back to a
graph we can draw and explain. So we combined a classic causal method (the PC algorithm) with simple machine
learning models.

\section{Related Work}
We group earlier work into four lines and close with the gap that our project fills (Table~\ref{tab:lit}).

\textbf{Causal graphs and discovery from independences.} Pearl~\cite{pearl1988,pearl2009} gave the theory of
Bayesian networks and of reasoning with causal graphs, and d-separation~\cite{geiger1990} turns ``independent
given $Z$'' into a rule that can be read off a graph. Verma and Pearl~\cite{verma1990} showed that two DAGs imply
the same independences exactly when they share the same skeleton and the same colliders, so data can only identify
a \emph{Markov equivalence class} (MEC), drawn as a partly directed graph~\cite{andersson1997}. The PC
algorithm~\cite{spirtes2000} recovers this class from independence tests, and Meek's rules~\cite{meek1995} orient
every edge that can be oriented. PC is consistent even with many variables~\cite{kalisch2007}. Score-based
search such as GES~\cite{chickering2002} and continuous optimisation such as NOTEARS~\cite{zheng2018} are
alternatives, but they need numeric data, while Corr2Cause only gives the independences as text.

\textbf{Causal relation extraction from text.} Early systems found cause--effect pairs with hand-written lexical
and syntactic patterns~\cite{khoo2000,girju2003}. SemEval-2010 Task~8~\cite{hendrickx2010} made cause--effect one
of nine relation classes between noun pairs, and BECauSE~2.0~\cite{dunietz2017} and the Causal News
Corpus~\cite{tan2022} annotate causal language in running text. These works find \emph{what the text claims}
about causes. They do not check whether a claim \emph{follows} from statistical evidence, and they do not produce
a graph that can answer intervention questions.

\textbf{Causal reasoning benchmarks for language models.} Corr2Cause~\cite{jin2024} asks whether a causal claim
follows from a list of correlations and independences. Its authors found that 17 large language models score close
to chance. Fine-tuned BERT-style models score highly on the original test set, but their scores drop sharply when
the hypotheses are paraphrased or the variable names are changed, so they learn surface patterns rather than the
reasoning. CLadder~\cite{jin2023cladder} tests all three rungs of Pearl's ladder with text questions built from
causal graphs, and K\i c\i man et al.~\cite{kiciman2023} and Ze\v{c}evi\'c et al.~\cite{zecevic2023} argue that
LLMs repeat causal facts they have seen rather than reason causally. Corr2Cause is framed as natural language
inference, the same premise--hypothesis format as MNLI~\cite{williams2018}.

\textbf{Neuro-symbolic AI.} Neuro-symbolic systems let a learned component read the input and a symbolic component
do exact reasoning~\cite{garcez2023}. The project brief asks for this split: text extraction proposes relations,
and the graph stage enforces acyclicity, quantifies uncertainty and answers interventions.

\textbf{Feature engineering and models.} We use TF-IDF~\cite{salton1988} for text, filter-based feature
selection~\cite{guyon2003} with chi-squared and mutual information~\cite{kraskov2004}, logistic regression, Random
Forest~\cite{breiman2001} and gradient boosting~\cite{friedman2001} from scikit-learn~\cite{pedregosa2011}, the
bootstrap~\cite{efron1993} for confidence intervals, and pgmpy~\cite{ankan2015} for PC and Bayesian networks.

\section{Theoretical Background}
\textbf{Bayesian networks.} A DAG $G$ over variables $V_1,\dots,V_n$ with parents $\mathrm{Pa}(V_i)$ and a
probability table at each node defines
\begin{equation}
P(v_1,\dots,v_n) = \prod_{i=1}^{n} P\big(v_i \mid \mathrm{pa}(v_i)\big).
\label{eq:factor}
\end{equation}
Under the causal Markov and faithfulness assumptions, the independences in the data are exactly the
d-separations in the graph:
\begin{equation}
X \perp\!\!\!\perp Y \mid Z \;\text{ in } P \iff X \perp_{G} Y \mid Z .
\end{equation}
A path is blocked by $Z$ if it has a non-collider in $Z$, or a collider $X\!\to\!W\!\leftarrow\!Y$ such that
neither $W$ nor any descendant of $W$ is in $Z$.

\textbf{Equivalence class and labels.} The Markov equivalence class $\mathcal{M}$ of a premise is the set of DAGs
whose d-separations match the premise, which are the DAGs with the same skeleton and colliders~\cite{verma1990}.
For a hypothesis $h$ and a DAG $G$, let $h(G)\in\{0,1\}$ say whether the claim holds in $G$. Corr2Cause labels a
hypothesis valid only if it holds in every member, and we measure how close it is to that with
\begin{equation}
y(h) = \prod_{G\in\mathcal{M}} h(G), \qquad
\text{mec\_support}(h) = \frac{1}{|\mathcal{M}|}\sum_{G\in\mathcal{M}} h(G).
\label{eq:mec}
\end{equation}

\textbf{PC algorithm.} PC starts from the complete undirected graph. It removes the edge $X - Y$ if some set $S$
of neighbours makes them independent, $X \perp\!\!\!\perp Y \mid S$, and stores $S$ as their separating set.
For every non-adjacent pair $X, Y$ with a common neighbour $Z \notin S_{XY}$, it orients the collider
$X \to Z \leftarrow Y$. Meek's rules then orient every remaining edge whose direction is forced. The output
represents exactly the class $\mathcal{M}$.

\textbf{Interventions.} Forcing $X=x$, written $do(X=x)$, removes the arrows into $X$. Dropping the factor of $X$
from Eq.~(\ref{eq:factor}) gives the truncated factorisation
\begin{equation}
P\big(v \mid do(X{=}x)\big) = \prod_{i:\,V_i \neq X} P\big(v_i \mid \mathrm{pa}(v_i)\big)\Big|_{X=x},
\end{equation}
and when $\mathrm{Pa}(X)$ blocks every back-door path, the back-door adjustment gives
$P(y \mid do(x)) = \sum_{z} P(y \mid x, z)\,P(z)$ with $Z = \mathrm{Pa}(X)$~\cite{pearl2009}. We report the
average causal effect
\begin{equation}
\mathrm{ACE}(X\!\to\!Y) = P(Y{=}1 \mid do(X{=}1)) - P(Y{=}1 \mid do(X{=}0)).
\label{eq:ace}
\end{equation}

\textbf{Text features.} With $n$ documents, term frequency $\mathrm{tf}$ and document frequency $\mathrm{df}$,
sublinear TF-IDF is
\begin{equation}
w_{t,d} = \big(1 + \ln \mathrm{tf}_{t,d}\big)\Big(\ln\frac{1+n}{1+\mathrm{df}_t} + 1\Big),
\end{equation}
and each document vector is scaled to unit length. Mutual information
$I(F;Y) = \sum_{f,y} p(f,y)\log\frac{p(f,y)}{p(f)\,p(y)}$ ranks features by how much they reduce uncertainty about
the label, including non-linear relations.

\textbf{Classifiers.} Logistic regression fits $p_i = \sigma(\beta^\top x_i + \beta_0)$ by minimising the
class-weighted log-loss with an $L_2$ penalty,
\begin{equation}
\min_{\beta}\; \frac{\lVert\beta\rVert^2}{2} - C\sum_{i} w_{y_i}\big[y_i \ln p_i + (1-y_i)\ln(1-p_i)\big],
\end{equation}
with class weights $w_c = n/(2\,n_c)$, so the rare valid class counts as much as the common one. Random Forest averages deep trees grown on bootstrap
samples, each split chosen to reduce the Gini impurity $1-\sum_k p_k^2$. Gradient boosting builds
$F_m = F_{m-1} + \nu\, h_m$, where each small tree $h_m$ fits the negative gradient of the log-loss and $\nu$ is the
learning rate.

\textbf{Evaluation.} With precision $P$ and recall $R$, $F_1 = 2PR/(P+R)$. Rows that share a premise are not
independent, so confidence intervals use a cluster bootstrap: resample whole premises with replacement, recompute
$F_1$, and take the 2.5th and 97.5th percentiles.

\section{Step 1: Cleaning the Data (Notebook 01)}
We used the official train, validation and test splits from Hugging Face (Table~\ref{tab:data}). Each row has
the text (\texttt{input}), the \texttt{label}, the number of variables, and a \texttt{template} that says which
type of claim it is.

\textbf{Checking the data.} We looked at the first and last rows, the shape and the column types. We counted
missing values and duplicate rows. There were none, so nothing had to be filled in or removed.

\textbf{Cleaning.} Every text has one ``Hypothesis:'' marker, so we split it into two columns:
\texttt{premise} and \texttt{hypothesis}. We also removed extra spaces. The same premise is reused with up to 90
different claims, so we gave each premise an ID number.

\textbf{Removing leakage.} A few premises appeared in two splits at once (2 in train and validation, 3 in
validation and test). If the model sees a premise during training and again in testing, its score looks better
than it really is. We left the test set as it was and removed these shared premises from train and validation.

\textbf{Making train smaller.} Train has about 206{,}000 rows, which is slow to work with. We randomly picked
400 premises (seed 42) and kept all of their claims, giving 35{,}340 rows. The share of valid claims stayed the
same (18.5\%).

\textbf{Few valid claims.} Only 13--19\% of claims are valid (Fig.~\ref{fig:eda}, left). A lazy model that
always answers ``not valid'' would already be over 80\% accurate. So accuracy is misleading here. Instead we use
\emph{precision} (of the claims we called valid, how many really were), \emph{recall} (of the truly valid
claims, how many we found) and \emph{F1} (one number that balances the two). We also told the models to give
more weight to the rare valid class.

\textbf{A hidden shortcut.} ``Child'' claims are never valid (Fig.~\ref{fig:eda}, right), yet their text
(``X directly causes Y'') looks exactly like ``parent'' claims. So the \texttt{template} column gives away the
answer. We did not use it as a feature; we only used it later to study mistakes.

\textbf{Harder test set.} Train only has graphs with 5--6 variables, but validation and test also have graphs
with 2--4 variables. So the test set includes some cases the model never saw in training.

\section{Step 2: Text to Graph (Notebook 02)}
\textbf{Reading the text.} The sentences follow fixed patterns, so simple regular expressions are enough. From
each claim we pick out the two variables (single capital letters) and the claim type (direct cause, indirect
cause, common effect, common cause) using keywords. We also added safety checks: a variable must be one of A--F
and must appear in the premise, a variable cannot cause itself (A$\to$A), and unknown wording is rejected. All
real rows passed, and broken examples we made by hand were caught.

\textbf{Running PC.} PC normally needs numeric data to test for independence. Here the premise already tells us
which pairs are independent, so we let pgmpy's PC read those facts directly
(\texttt{ci\_test="independence\_match"}). PC then (1) starts with all pairs linked and removes links between
independent pairs, (2) finds patterns like X$\to$Z$\leftarrow$Y, where Z is a common effect, and (3) applies its
fixed rules to set more directions. Links it cannot decide are left undirected (Fig.~\ref{fig:pc}).

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{pc_graphs}
\caption{PC output for two premises. Solid arrows have a known direction; dashed lines could point either way.
Left: E is a common effect of A--D. Right: only A and B are linked, and C stands alone.}
\label{fig:pc}
\end{figure}

\textbf{Counting fitting graphs.} For each undirected link we try both directions. We keep every version that
has no loops and fits the same independence facts. This gives us all the DAGs in the equivalence class, between
1 and 144 per premise. For each claim we then compute mec\_support, the share of these DAGs where the claim is
true (Eq.~\ref{eq:mec}). If it is 1, the claim holds in every fitting graph, so it should be valid.

\textbf{What does each claim mean?} Our first definitions were the textbook ones: a collider is a shared direct
child, a confounder a shared direct parent, and ``X causes something else which causes Y'' means Y is a
descendant of X but not a direct child. With these, the mec\_support rule matched only 93.7\% of train labels.
So we read the code that generated the labels~\cite{corr2causecode}. It walks every path between X and Y and
names the path by its arrows (Table~\ref{tab:claims}). Two differences matter. First, ``X causes something else
which causes Y'' only needs a path of two or more arrows, even if X$\to$Y also exists. Second, colliders and
confounders can be reached through longer paths, and a loop in the generator that counts the wrong way means a
confounder only counts when the common cause is directly linked to the second variable.

\begin{table}[t]
\centering
\caption{Claim definitions used by the Corr2Cause generator}
\label{tab:claims}
\footnotesize
\begin{tabular}{ll}
\toprule
Claim & A path from X to Y \\
\midrule
X directly causes Y & X$\to$Y \\
X causes sth.\ else which causes Y & X$\to\dots\to$Y (2+ arrows) \\

\bottomrule
\end{tabular}
\end{table}

With these definitions the same no-learning rule matches 96.6\% of train, 97.5\% of validation and 98.5\% of test
labels. The largest group of remaining mismatches (41\%) are ``parent'' claims where every fitting DAG has the
arrow X$\to$Y but the label is 0. We treat these as label noise; a public audit of the test split also reports
wrong labels in both directions. We also noticed that the letters follow the causal order: across all 440
premises, PC never points an arrow from a later letter to an earlier one. This is why ``child'' claims, which
always name the later letter as the cause, are never valid.

\section{Step 3: Building Features (Notebook 03)}
A model cannot read text or graphs directly, so we turn each claim into a row of numbers called features.

\textbf{Graph features (15).} The claim type (one column per type); how many correlations and independences the
premise lists; whether X and Y are said to correlate, to be independent, or to be independent once other
variables are known; whether PC drew X$\to$Y, Y$\to$X or an undirected X--Y; the number of fitting DAGs (on a log
scale); and mec\_support. We rescaled these to a similar range, using only train data to set the scale.

\textbf{Text features.} TF-IDF gives each word or word pair a score: high if it appears often in this text but
rarely in others. We made one TF-IDF table for the premise (135 terms) and one for the claim (106 terms), learned
from train only. We kept one-letter words because A--F are the variable names.

\textbf{Which features matter?} We scored each feature by how much it tells us about the label (mutual
information, Fig.~\ref{fig:mi}). The 0/1 and count features were treated as discrete and the other two as
continuous. mec\_support is far ahead of everything else, followed by the arrow-direction features. The top text
words are things like ``collider'' and variable letters, which say nothing about the specific pair being asked
about. Keeping only the top 80 text terms changed F1 by about 0.02 (0.88 vs 0.90), which is within the noise of
a 19-premise validation set, so we kept all of them.

\section{Step 4: Training and Testing Models (Notebook 04)}
\textbf{Setup.} Each claim becomes 256 numbers (text + graph features). We tried three models: logistic
regression, Random Forest (300 decision trees voting together) and gradient boosting (small trees added one
after another, each fixing the last one's mistakes). For each model we tried a few settings with
\texttt{GridSearchCV} and 5-fold cross-validation.

One detail matters here: we used \texttt{GroupKFold}, which keeps all claims of the same premise in the same
fold. Otherwise the model could see a premise in training and be checked on the same premise, which would make
the score look too good. We picked the model with the best validation F1, and used the test set only once, at
the very end.

\textbf{Results.} Random Forest had the best validation F1, so we chose it (Table~\ref{tab:results}) and used
the test set only to report it. It is slightly better than the plain mec\_support rule on both validation
(0.929 vs 0.906) and test (0.957 vs 0.952), but the test gap is well inside the confidence interval below. The
honest reading is that the symbolic step does almost all of the work once the claim definitions are right, and the
learned model mainly tidies up the edges of that rule. This is the neuro-symbolic split the brief asks for:
the text step proposes, the graph step decides.

\textbf{How sure are we?} The test set has only 21 premises, so the score could change with a different test
set. To check, we re-sampled whole premises 1{,}000 times (the bootstrap) and recomputed F1 each time. The F1
stayed between 0.921 and 0.982 in 95\% of the runs.

\textbf{Where it goes wrong.} The model made 16 mistakes out of 1{,}162 (Fig.~\ref{fig:cm}). Half are false

claims. Graphs with 2--4 variables, which never appeared in training, had 1 mistake in 126 rows (0.8\%), against

memorised sentences.

\section{Step 5: Drawing the Graph and Asking ``What If'' (Notebook 05)}
\textbf{Building the DAG.} For each test premise, every ``X directly causes Y'' claim that the model calls valid
becomes an arrow. We add arrows starting with the ones the model is most sure about. An arrow is skipped if it
points from a variable to itself, uses a variable not in the premise, or would create a loop. All 21 test graphs
came out as proper DAGs. Out of 73 arrows drawn, 65 are correct (\textbf{precision 0.89}), and no true arrow was
missed (recall 1.00). All 8 wrong arrows are also drawn by PC, so they come from the same label disagreement as
before (Fig.~\ref{fig:dag}).

\begin{figure}[t]
\centering
\includegraphics[width=0.82\linewidth]{dag_vs_truth}
\caption{One test premise. Left: the true arrows. Right: our predicted DAG. Blue arrows are correct; the two red
arrows (B$\to$E, A$\to$F) are extra ones that PC supports but the dataset marks as not valid.}
\label{fig:dag}
\end{figure}

\textbf{Bayesian network and ``what if'' questions.} A Bayesian network is a DAG with probabilities attached to
each node. It lets us ask ``what happens to Y if we \emph{force} X to a value?'', written $do(X)$. This is
different from just observing X, and it is the real test of cause and effect.

Corr2Cause has no numbers, only text, so we made some. We gave the true graph random probabilities, generated
5{,}000 samples from it, and fitted our predicted DAG on those samples with pgmpy. Then we measured the effect of X
on Y with the ACE of Eq.~(\ref{eq:ace}). For the chain A$\to$B$\to$C, the true effect of A on C is 0.490 and our
correctly drawn graph gives 0.498. If the arrows are reversed, the graph still fits the same data but gives 0.000,
and wrongly says that C affects A.

\textbf{Intervention queries.} We used the five test premises whose graph is fully known (one DAG in the
class). Each premise gets its own random probabilities, and we ask about every ordered pair of variables in both
directions: 96 queries, 32 of which have a real effect. A query counts as correct only if the graph gets both
whether there is an effect at all (a directed path) and its size within 0.05. The first condition stops a tiny
true effect from ``matching'' a graph with no arrow. Table~\ref{tab:queries} compares our DAGs with two
baselines fitted on the same data.

Our DAGs answer 28 of the 32 real effects correctly; both baselines answer none. All four misses come from one
premise where the model left out C$\to$D and C$\to$E, two arrows that PC says are certain but the dataset labels
as not valid. So getting the arrows right, in the right direction, is what makes the ``what if'' answers right.

\section{Conclusion and Next Steps}
Turning the text into a graph with a parser and the PC algorithm, using the claim definitions of the dataset's
own generator, explains 97--98\% of the labels with no learning. Adding these graph features to simple text
features and training a Random Forest gives a test F1 of 0.957 (95\% CI 0.921--0.982), with no data leaking
between splits. Text features alone reach only 0.47, which supports the brief's point that fluent text features
cannot replace formal causal reasoning. Most remaining mistakes come from a small set of labels that disagree with
PC.

\textbf{Limitations.} Corr2Cause is generated from templates, so our regex parser would not work on paraphrased or
real text, and the letters follow the causal order, which a model could exploit. Train only has 5--6 variable
premises. The Bayesian network data is simulated from the PC graph, not measured.

\textbf{Phase 2.} We plan to replace the regex parser and TF-IDF with a fine-tuned transformer that reads
paraphrased text, keep PC for the reasoning, and test both on paraphrased and renamed-variable versions of the
data, where the Corr2Cause authors found fine-tuned models break down.
