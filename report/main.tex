\begin{abstract}
Corr2Cause asks whether a causal claim (e.g.\ ``A directly causes B'') must follow from a set of
correlation and independence statements written in text. We built a fully reproducible pipeline of five
notebooks: data cleaning and leakage removal, a rule-based parser with the PC causal discovery algorithm,
TF-IDF plus structured graph features, three tuned classifiers, and a DAG and Bayesian network built from the
predictions. Text features alone reach an F1 of 0.47 on validation; adding the graph features raises it to
0.80. The chosen Random Forest reaches a test F1 of 0.905 (95\% CI 0.852--0.937), the predicted edges have a
precision of 0.89, and a Bayesian network fitted on our DAGs answers all five intervention queries within 0.05
of the true graph.
\end{abstract}

\section{Introduction}
Large language models often treat correlation as causation. Corr2Cause~\cite{jin2024} tests this directly:
each example is a \emph{premise} that lists, for a closed system of 2--6 variables, which pairs correlate and
which are (conditionally) independent, and a \emph{hypothesis} about a causal relation. The label is 1 only
if the hypothesis holds in \emph{every} causal graph consistent with the premise. Our goal in Phase~1 is to
solve this with classical machine learning and explicit causal reasoning instead of a black box, so every
prediction can be traced back to a graph.

\section{Literature Review}
Causal graphs and interventions are formalised by Pearl~\cite{pearl2009}. The PC algorithm~\cite{spirtes2000}
recovers a causal graph from conditional independences: it removes edges between independent pairs, orients
colliders and then applies Meek's rules~\cite{meek1995}. The result is a CPDAG, which represents a Markov
equivalence class (MEC) of DAGs that share the same skeleton and colliders~\cite{verma1990}. Jin et
al.~\cite{jin2024} built Corr2Cause from exactly this theory and showed that fine-tuned language models fail
to generalise on it, and K\i c\i man et al.~\cite{kiciman2023} report similar gaps in LLM causal reasoning. For
the ML side we use TF-IDF~\cite{salton1988}, logistic regression, Random Forests~\cite{breiman2001} and gradient
boosting~\cite{friedman2001} from scikit-learn~\cite{pedregosa2011}, the bootstrap~\cite{efron1993} for
confidence intervals, and pgmpy~\cite{ankan2015} for PC and Bayesian networks. Our contribution is to combine
the symbolic PC output with learned models and to measure how much each part helps.

\section{Dataset and Quality Checks (Notebook 01)}
We use the official Hugging Face splits of Corr2Cause (Table~\ref{tab:data}). Each row has an \texttt{input}
text, a binary \texttt{label}, \texttt{num\_variables} and a \texttt{template} (the hypothesis type).

\textbf{Inspection.} We used \texttt{head()}, \texttt{tail()}, \texttt{shape} and \texttt{info()} to look at the
structure, \texttt{isnull().sum()} to count missing values and \texttt{duplicated().sum()} to count duplicate
rows. There were no missing values and no duplicate rows in any split, so no imputation or row removal was
needed.

\textbf{Cleaning.} Every \texttt{input} contains exactly one ``Hypothesis:'' marker, so we split it into a
\texttt{premise} and a \texttt{hypothesis} column, collapsed repeated whitespace, and dropped the original
\texttt{input} column. We checked that the number of variables written in each premise matches
\texttt{num\_variables} (0 mismatches). Each premise was given a \texttt{premise\_id}, because one premise is
reused with up to 90 hypotheses.

\textbf{Leakage.} Two premises were shared between train and validation and three between validation and test.
We kept the test set untouched and removed the shared premises from validation and train, after which no
premise appears in two splits.

\textbf{Subsampling.} Train has 205{,}734 rows. We sampled 400 whole premises (seed 42), keeping all their
hypotheses, which gives 35{,}340 rows. The share of label 1 is the same before and after (0.185).

\section{Parsing and the PC Algorithm (Notebook 02)}
\textbf{Parser.} The text is template-generated, so regular expressions are enough. The two variables of a
hypothesis are its single capital letters, and its relation (direct cause, indirect cause, collider,
confounder) is found from keywords. Schema rules reject variables outside A--F, self-loops (A$\to$A), variables
not declared in the premise and unknown wording; all rows passed, and hand-made broken examples were caught.

\textbf{PC algorithm.} PC normally runs statistical tests on numeric data. Here the premise states the
independences, so we pass them to pgmpy's PC as an oracle (\texttt{ci\_test="independence\_match"}). PC (i)
starts from a complete graph and removes edge $X\!-\!Y$ whenever $X \perp Y \mid S$ is stated, (ii) orients
$X\!\to\!Z\!\leftarrow\!Y$ when $X,Y$ are not adjacent and $Z\notin S$, and (iii) applies Meek's rules. Edges
it cannot orient stay undirected (Fig.~\ref{fig:pc}).

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{pc_graphs}
\caption{PC output for two premises. Solid arrows are edges whose direction is certain, dashed lines are edges
that can point either way. Left: E is a collider of A--D. Right: only A--B is connected and C is isolated.}
\label{fig:pc}
\end{figure}

\textbf{Equivalence class and support.} For every undirected edge we try both directions and keep the
orientations that are acyclic and I-equivalent to the PC graph; these are all DAGs in the MEC (1 to 144 per
premise). For a hypothesis $h$ we define
\begin{equation}
\text{mec\_support}(h) = \frac{1}{|\mathcal{M}|}\sum_{G\in\mathcal{M}} \mathbb{1}[h \text{ holds in } G],
\end{equation}
where $\mathcal{M}$ is the MEC. The rule ``valid iff mec\_support $=1$'' reproduces 93.7\% (train), 96.5\%
(validation) and 96.2\% (test) of the labels, which confirms that the parser is correct. The remaining
disagreements are cases where the dataset's label differs from PC's conclusion.

\section{Feature Engineering and Selection (Notebook 03)}
\textbf{Structured features (15).} Claim type (one-hot); counts of correlations and independences; whether the
premise says $X,Y$ correlate, are independent, or are independent given others; whether PC drew $X\!\to\!Y$,
$Y\!\to\!X$ or an undirected $X\!-\!Y$; $\log|\mathcal{M}|$; and \texttt{mec\_support}. There are no missing
values, and the features are standardised with a scaler fitted on train only.

\textbf{Text features.} Separate TF-IDF vectorisers (unigrams and bigrams, min\_df $=2$) for premise (135
terms) and hypothesis (106 terms), fitted on train only. The token pattern keeps one-letter words because A--F
are the variable names.

\textbf{Selection.} Chi-squared scores show that the top text terms are claim words (``collider'') and variable
letters, which carry no reasoning about the specific pair. Mutual information (Fig.~\ref{fig:mi}) ranks
\texttt{mec\_support} far above everything else, followed by the edge-direction features. Keeping only the top
50+30 TF-IDF terms changes validation F1 very little (0.80 vs 0.82), so we keep all terms.

\section{Models and Evaluation (Notebook 04)}
\textbf{Setup.} The inputs are TF-IDF + scaled structured features (256 columns), fitted on train only. We tuned
three models with \texttt{GridSearchCV} and 5-fold \texttt{GroupKFold} grouped by premise, so all hypotheses of a
premise stay in the same fold and the CV score is not inflated. All models use balanced class weights:
logistic regression ($C\in\{0.1,1,10\}$), Random Forest (300 trees, depth and leaf size) and histogram
gradient boosting (learning rate and leaf count). The model is chosen by validation F1, and the test set is
used once at the end.

\textbf{Results.} Random Forest had the best validation F1 and was selected (Table~\ref{tab:results}).
Gradient boosting scores higher on test, but changing the model after seeing test results would be test-set
tuning, so we keep the validation choice. The learned model beats the pure rule (F1 0.871) mainly through
higher recall. A premise-level bootstrap (1{,}000 resamples of whole premises, since rows of one premise are
not independent) gives a 95\% CI of 0.852--0.937 for the test F1.

\textbf{Error analysis.} Of the 36 errors (Fig.~\ref{fig:cm}), 14 are false alarms on collider claims and 8 on
parent claims, the same types where PC and the dataset labels disagree in notebook 02. ``Child'' claims have no
errors. The 2--4 variable graphs, never seen in training, have a similar error rate (4.0\%) to the 5--6
variable graphs (3.0\%), because the structured features come from the parser and PC rather than from
memorised sentences.

\section{DAG Construction and Bayesian Network (Notebook 05)}
\textbf{DAGs.} Every ``X directly causes Y'' claim predicted as valid becomes a candidate edge. Edges are added
most confident first and are skipped if they are self-loops, use a variable outside the premise, or would
create a cycle; all 21 test graphs are valid DAGs. Out of 73 drawn edges, 65 are true, giving an
\textbf{edge precision of 0.89} and an edge recall of 1.00. All 8 wrong edges are supported by the PC graph
(precision 1.00 against PC), so they come from the same label disagreement (Fig.~\ref{fig:dag}).

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{dag_vs_truth}
\caption{True edges (left) and our predicted DAG (right) for one test premise. Blue edges are correct; the two
red edges (B$\to$E, A$\to$F) are extra edges that PC supports but the dataset labels as invalid.}
\label{fig:dag}
\end{figure}

\textbf{Bayesian network and interventions.} Corr2Cause has no numeric data, so we gave the true graph
conditional probability tables, simulated 5{,}000 samples and fitted our DAG on them with pgmpy (Bayesian
estimator, BDeu prior). The causal effect is $P(Y{=}1\mid do(X{=}1)) - P(Y{=}1\mid do(X{=}0))$. On the chain
A$\to$B$\to$C the true effect of $do(A)$ on C is 0.490 and the correctly oriented graph gives 0.498, while the
reversed graph fits the same data but gives 0.000 and wrongly claims that C affects A. On the five test
premises whose graph is fully known, all five intervention answers from our network match the true graph
within $\pm 0.05$. Correct edge directions are therefore what make the causal answers correct.

\section{Conclusion and Phase 2}
A parser and the PC algorithm turn text into causal graphs that explain 94--96\% of the labels, and combining
these graph features with TF-IDF in a Random Forest gives a test F1 of 0.905 with clean, leakage-free splits.
The main limitation is the small set of labels that disagree with PC, which accounts for most remaining errors.
In Phase~2 we plan to replace TF-IDF with a fine-tuned transformer encoder and combine it with the PC features
as a hybrid model, with ablations to show what each part adds.
